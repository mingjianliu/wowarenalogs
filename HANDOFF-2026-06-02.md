## P1 — Logic / correctness / maintainability

### 3. De-duplicate the dispel-correlation logic

- **Commit:** `02e447fa` (F148 Cleanse Success Verification).
- **Problem:** Good fix (previously _any_ short CC was miscounted as a cleanse). But the "was this CC removed by a friendly dispel within 0.5s?" predicate now exists in two places: `dispelAnalysis.ts` (`reconstructDispelSummary`) and the `[CLEANSED]` tag in `matchTimeline.ts`.
- **Why it matters:** If you ever tune the 0.5s tolerance you must find both copies or they diverge.
- **Fix:** Extract `wasRemovedByAllyDispel(allyCleanse, spellId, targetName, removalSeconds): boolean` and call it from both sites. Document the behavior change (short, non-dispelled, non-damage-broken CC now counts as _nothing_, where it used to count as a cleanse).

### 4. Extract the shared prompt "five checks" prose

- **Commit:** `de988845` (F137+F150 perspective anchoring).
- **Problem:** The entire five-check block (Identity Grounding, Trade Equity, Overlap Attribution, Counterfactual Path, Specific Future Consequence) is copy-pasted in both the text (`[RES]`) and JSON (`[SIT]`) prompt variants in `analyzeSystemPrompts.ts`. Only the field-description paragraph genuinely differs.
- **Why it matters:** You correctly added check #5 to both copies this time, but the next edit will touch one and they'll silently drift.
- **Fix:** Pull the shared check prose into a single `const CHECKS_BLOCK = ...` and interpolate the format-specific field-descriptions per variant. Land the `[OWNER]/[TEAMMATE]` → `[YOU]/[TEAM]` tag rename as its own mechanical commit, separate from new prompt rules.

### 5. CC-avoidance: label inference as inference; handle refresh

- **Commit:** `e1819942` (CC avoidance tracking; also bundled a prompt-comparison pipeline — should have been two commits).
- **Problem:** The code asserts "CC X was avoided _because of_ buff Y" from temporal correlation alone (a tracked buff was active when a CC cast landed and no CC instance appeared within 1.5s). A LoS'd / missed / resisted cast while a buff happens to be up gets mislabeled as an active avoidance. This injects a verdict, not a fact — counter to the `feedback_comp_heuristics` principle.
- **Why it matters:** The model consumes this as ground truth.
- **Fix:**
  - Soften the timeline label to inference: `[CC AVOIDED?]` or "likely mitigated by …" rather than asserting causation.
  - Handle `SPELL_AURA_REFRESH` in the buff-interval reconstruction in `ccTrinketAnalysis.ts` — currently a refresh isn't tracked, so a refreshed buff's active window can be computed wrong.

### 6. Resolve the F136 healer-metrics bias reversal with data

- **Commits:** `269caab3` ("add healer metrics to dashboard **and remove from AI prompt to avoid bias**"), `434ba145` ("**inject** match-end healer performance metrics **into prompt**").
- **Problem:** A stated design decision (remove healer numbers to avoid biasing the model) was reversed two days later with no documented rationale.
- **Why it matters:** This is precisely the kind of question your `evalPromptCompare` harness exists to settle.
- **Fix:** Run control (no healer metrics) vs treatment (match-end metrics) through the harness; cite the judge result in the commit message instead of asserting a hunch. Then remove the losing branch.
